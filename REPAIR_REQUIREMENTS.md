# The successful workflows I would require

I would measure a repair by whether an ordinary manager can finish an authorized action with valid evidence. A refusal message and a large passing-test count answer only part of that question. I would retain controls for sleeve ownership, settled capital, commissioned transport, quotes, idempotency, reconciliation and uncertain submissions.

## Preserve investment judgment through an execution failure

I would keep the adopted action, quantities, intended economics, expiry and fresh-evidence requirements separate from execution state. A failed quote, incomplete operator or broken projection must not silently turn an adopted BUY or SELL into an economic rejection. A repaired route needs a fresh manager checkpoint; an expired decision must not be replayed.

For each deferred decision I would require a precise trigger, a responsible owner and an expiry. When the trigger is satisfied or the deadline arrives, the manager must make a new terminal disposition. Repeating the old blocker is not completion.

## Prove the ordinary positive path

I would require an acceptance case that starts with permitted source inputs and uses documented public operators. It must produce the required receipts, build the request, run preflight and reach the correct execution state in a broker-free simulator. Directly inserting a READY row can test downstream lifecycle behavior, but it cannot establish the acquisition and authoring workflow.

For every compulsory predicate I would record its authority, producer, consumer, action scope and passing example. A requirement with no available producer needs a finite delivery plan. A useful analysis field should not become an execution prerequisite simply because it appears in a readiness report.

## Challenge policy accumulation

I would periodically ask which principal or manager decision commissioned each restriction, whether its scope still matches the action, and what observation would revise it. Historical precision targets, another manager's cutoff or a retired reporting contract should not acquire authority through repeated model text.

A stage policy should compare opportunity costs as well as drawdown and evidence quality. Assigned capital, settled cash, an internal deployment stage and order capacity are distinct quantities. Missing performance history needs a realistic acquisition plan; a requirement that depends on an event that may never happen needs a reconsideration trigger.

## Test my own decision biases

I would use paired, blinded offline cases rather than a target trade count. Requiring more trades could create an equally poor bias toward action.

- Hold relevant economics fixed while changing irrelevant prior HOLD wording, neutral asset names and presentation order. Assess whether the disposition changes without a stated economic reason.
- Present a fully eligible authorized action, then introduce one valid execution block. Assess whether the model preserves investment judgment, identifies the actual control and avoids invented approvals.
- Satisfy a previous deferral trigger using fresh evidence. Assess whether the model reassesses or repeats an obsolete refusal.
- Compare BUY, owned SELL and risk-reducing exits using comparable evidence burdens. Allow justified disagreement and no trade in the scoring rubric.
- Present an incomplete unrelated report alongside a complete action-specific decision. Assess whether completeness anxiety masks the supported action.

I would fix model versions and settings, randomize order, record the rubric and evaluate independent contexts. These checks can reveal observable inertia, irrelevant framing sensitivity and authority confusion. They cannot identify hidden training causes or prove that a chosen trade is optimal.

I have not implemented these repairs or changed investment policy in this audit. They are concrete acceptance requirements for a subsequent authorized engineering effort.
