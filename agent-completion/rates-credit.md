This is not evidence that the tests were fake or that the source writer does nothing. It also demonstrated a shared SELL/CLOSE alpha hurdle and a six-second stale-report rejection. [The bounded reproduction report](../cases/rates-credit.md) records those distinctions.

My criticism is that software acceptance, fixture success, source availability and ordinary manager usability need separate completion states. A commissioned builder with authentic inputs still unresolved has not delivered the whole trading capability. Repeated audit, commissioning and protocol milestones can displace the original functional goal if no one owns the last step: an authentic current request through the ordinary path, or a precise remaining source/method/authority blocker with an accountable repair outcome.

I would assess progress by calibrated research coverage, authentic request construction, valid risk-reducing exit reachability, and time from adopted decision to usable execution. I would keep fixture counts and document checks as supporting evidence. No safety bypass or mandatory trade follows from that standard.

My own review must resist the same substitution: a large census is coverage work, not proof of trading competence; an agent label is not an accessible prompt; a high return objective is not authorization to manufacture turnover.
